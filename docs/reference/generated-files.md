# 生成物契约

四类产物、一个生产者：`pipeline/` 是唯一写入 `assets/generated/`、`worker/targets.js`、`worker/slot_formats.js` 的代码；`dist/` 由 Vite 装配。

| 产物 | 是否入库 | 谁生成 | 谁消费 | 出处 |
| --- | --- | --- | --- | --- |
| `assets/generated/counts.json` | 是（池子其余部分被忽略） | `pipeline/manifest.py` | Vite 插件 → `dist/`、`src/` 前端 | `.gitignore`、`pipeline/manifest.py` |
| `assets/generated/<category>/<hex>.<ext>` | 否 | `pipeline/pool.py` | Vite 插件 → `dist/` | `.gitignore`、`vite.config.ts` |
| `worker/targets.js` | 是 | `pipeline/worker_targets.py` | `worker/policy.js` | `docs/architecture/layers.md` |
| `worker/slot_formats.js` | 是 | `pipeline/worker_targets.py` | `worker/index.js` | `docs/architecture/layers.md` |
| `dist/**` | 否 | `vite build` | `wrangler deploy`（`assets.directory`） | `.gitignore`、`wrangler.jsonc` |

## 1. `assets/generated/counts.json`

跨层的唯一数据契约：前端读分类/计数/逐槽比例，Worker 读槽位数与后缀（`contracts/manifest.schema.json` 的 `description`）。写入时用 `json.dump(meta, ensure_ascii=False, indent=2)` 与 `newline='\n'`，**字段顺序属于输出契约**（`pipeline/manifest.py`）。

### 顶层字段（9 个，顺序固定）

| 字段 | 类型 | 含义 | 出处 |
| --- | --- | --- | --- |
| `categories` | array | 分类展示元数据，按扫描顺序 | `pipeline/manifest.py` |
| `counts` | object | 每个分类的槽位数（`CategoryResult.slots`） | `pipeline/manifest.py` |
| `real_counts` | object | 每个分类的有效源图数量 | `pipeline/manifest.py` |
| `category_exts` | object | 每个分类的槽位后缀 | `pipeline/manifest.py` |
| `category_aspects` | object | 每个分类的宽高比，未知为 `null` | `pipeline/manifest.py` |
| `slot_ratios` | object | 分类 → 每槽宽高比数组，长度等于 `slots` | `pipeline/pool.py` |
| `hash_length` | integer | 槽位十六进制宽度，等于 `--hash-length` | `pipeline/manifest.py` |
| `output_ext` | string | 全局默认后缀，等于 `--ext` | `pipeline/manifest.py` |
| `generated_at` | string | ISO-8601 UTC，形如 `2026-10-27T03:45:52.470985Z` | `pipeline/manifest.py` |

当前实际取值：`hash_length` 为 `2`、`output_ext` 为 `.jpg`，四个分类各 `256` 槽（`assets/generated/counts.json`）。

### `categories[]` 子字段（8 个）

| 字段 | 类型 | 说明 | 出处 |
| --- | --- | --- | --- |
| `key` | string | 分类 key，与 `counts` 的键一致 | `pipeline/manifest.py` |
| `name_zh` | string | 中文名，可被 `assets/original/<key>/meta.json` 覆盖 | `pipeline/pool.py` |
| `name_en` | string | 英文名，同上 | `pipeline/pool.py` |
| `ext` | string | 该分类槽位后缀，匹配 `^\.[A-Za-z0-9]+$` | `contracts/manifest.schema.json` |
| `count` | integer | 等于 `real_counts[key]`（不是槽位数） | `pipeline/manifest.py` |
| `slots` | integer | 等于 `counts[key]` | `pipeline/manifest.py` |
| `aspect` | string \| null | 宽高比，如 `"4/3"`；动图为 `null` | `contracts/manifest.schema.json` |
| `aspect_hint` | string | 人读提示，如 `"4:3"`、`"动态格式"`、`"暂无素材"` | `pipeline/pool.py` |

### `generated_at` 复用规则

仅当已有 `counts.json` 的 `counts`、`real_counts`、`category_exts`、`slot_ratios`、`hash_length`、`output_ext` 六项全部相等时才沿用旧时间戳；否则重新生成（`pipeline/manifest.py`）。

刻意比 schema 窄：只改标签、`aspect_hint`、`category_aspects` 不会刷新时间戳，这样"内容未变"的重跑不会产生 diff。

### 校验与 schema

| 项 | 说明 | 出处 |
| --- | --- | --- |
| schema 位置 | `contracts/manifest.schema.json`，JSON Schema 2020-12 | 同上 |
| 校验时机 | `write_manifest` 写盘前调用 `validate_manifest`，失败抛 `ManifestError` | `pipeline/manifest.py` |
| 严格程度 | 根对象与 `categories[]` 元素都是 `additionalProperties: false`，加字段必须先改 schema | `contracts/manifest.schema.json` |
| 空分类 | `slots` 为 `0`、`count` 为 `0`、`aspect` 为 `null`、`slot_ratios` 为 `[]` | `pipeline/pool.py` |

## 2. `worker/targets.js`

```js
// Generated by `python -m pipeline`. Do not edit.
export const HASH_LENGTH = 2;
export const IMAGE_EXT = ".jpg";
export const TARGETS = JSON.parse("{\"a\": {\"dir\": \"a\", \"slots\": 256, \"ext\": \".jpeg\", \"label\": \"avatar\"}, ...}");
```

| 导出 | 来源 | 用途 | 出处 |
| --- | --- | --- | --- |
| `HASH_LENGTH` | `hash_length`，字面量输出 | 槽位补零宽度 | `pipeline/worker_targets.py` |
| `IMAGE_EXT` | `output_ext`，经 `json.dumps` | `TARGETS[x].ext` 缺失时的兜底后缀 | `pipeline/policy.js` |
| `TARGETS` | `counts` 的每个键：`dir` / `slots` / `ext` / `label` | `/pic?img=<key>` 的键集合、`parseCategoryImage` 的分类判定、重定向路径 | `worker/index.js`、`worker/policy.js` |

`TARGETS` 用的是**双重编码**：`json.dumps(json.dumps(targets, ensure_ascii=True))`，外层得到一个 JS 字符串字面量，导入时再 `JSON.parse`（`pipeline/worker_targets.py`）。这样做让生成器只输出数据、不输出可执行逻辑，模块可以完全按数据 review，且与历史输出的字节布局保持一致（`ensure_ascii=True` 保证非 ASCII 变成转义序列）。

**为何入库**：运行时 bundle 必须自带分类表，部署时不需要 Python；同时它是可复现产物，CI 重新生成后 diff 为空才算通过（`docs/architecture/layers.md` 的 invariant）。键按 `sorted(counts)` 排序，保证字节级稳定（`pipeline/worker_targets.py`）。

## 3. `worker/slot_formats.js`

```js
export const SLOT_FORMATS = JSON.parse("{\"a\": \"jwjwwjwwjjj...\", \"gif\": \"gggg...\", \"h\": \"jjjjjjjwww...\", \"v\": \"jjj...\"}");
```

| 项 | 说明 | 出处 |
| --- | --- | --- |
| 结构 | 分类 → 字符串，第 `i` 个字符描述第 `i` 号槽位的真实字节格式 | `pipeline/pool.py` |
| 字符集 | `j`=JPEG、`p`=PNG、`g`=GIF、`w`=WebP、`?`=无法识别 | `pipeline/formats.py::FORMAT_CODES`、`UNKNOWN_FORMAT_CODE` |
| 长度 | 等于该分类的 `counts[key]`，即当前 `--hash-length 2` 下的 `256` | `pipeline/worker_targets.py` |
| 空分类 | 空字符串，对应 0 个槽位 | `pipeline/worker_targets.py` |
| 键集合 | 与 `TARGETS` 相同的排序键集 | `pipeline/worker_targets.py` |
| 与 `counts.json` 的关系 | 两者描述同一个池：`SLOT_FORMATS[c]` 的长度 == `counts[c]`，槽位下标一致 | `pipeline/pool.py`、`pipeline/manifest.py` |

**为何需要它**：池子逐字复制源字节，后缀可以撒谎——一张 PNG 落在 `.jpeg` 槽位里（`a` 分类被 `ext_policy: ".jpeg"` 钉死，`pipeline/catalog.py`）。重命名会移动已部署 URL，所以不改名而是发布映射：`worker/index.js` 用 `SLOT_FORMATS[category][slot]` 决定 `Content-Type`（`j/p/g/w`），`?` 表示无证据、保留资产原始头。`targets.js` 与 `slot_formats.js` 一起写，半更新的一对会让每个请求都返回错误的 MIME（`pipeline/worker_targets.py`）。

## 4. `dist/` 结构

`vite build` 装配：Vite 多页产物 + `publicDir = assets/static` + 插件复制 `assets/generated`（`vite.config.ts`）。`assets/generated` 不存在时构建直接抛错，提示先跑 `npm run gen`。

```text
dist/
├── index.html  gallery.html  settings.html    # 三个 Vite 入口
├── assets/                                    # 内容哈希 bundle（main-*.js / main-*.css）
├── fonts/                                     # geist-latin.woff2、geist-mono-latin.woff2
├── icon.svg  placeholder.svg                  # 来自 assets/static/
├── _headers                                   # 来自 assets/static/_headers
├── counts.json                                # 来自 assets/generated/counts.json
├── a/     256 个文件  00.jpeg … ff.jpeg
├── gif/   256 个文件  00.gif  … ff.gif
├── h/     256 个文件  00.jpg  … ff.jpg
└── v/     256 个文件  00.jpg  … ff.jpg
```

| 项 | 来源 | 出处 |
| --- | --- | --- |
| 三个 HTML | `build.rollupOptions.input` 显式列出 `index` / `gallery` / `settings` | `vite.config.ts` |
| `assets/` | Vite 打包产物，文件名带内容哈希 | `vite.config.ts` |
| `fonts/`、`icon.svg`、`placeholder.svg`、`_headers` | `publicDir` 原样复制 | `vite.config.ts` |
| `counts.json`、各分类目录 | `closeBundle` 钩子从 `assets/generated` 串行复制 | `vite.config.ts` |
| `dist/` 本身 | `emptyOutDir: true`，每次构建清空，绝不手改 | `vite.config.ts`、`docs/architecture/layers.md` |

`assets.run_worker_first: true` 让这些文件仍然先经过 Worker，`_headers` 的缓存规则只在资产响应上生效（`wrangler.jsonc`）。字段如何被前端读取见 `src/components/image-gallery.tsx`，运行时如何使用 `slot_formats.js` 见 [api.md](./api.md) 第 7 节。
