# 开发与协作指南

本文涵盖本地开发命令、构建链路、代码规范、四套自动化测试，以及 GitHub Actions 测试与部署工作流。

## 1. 命令与构建顺序

### 常用命令

| 命令 | 实际执行 | 说明 |
| :--- | :--- | :--- |
| `npm run gen` | `python -m pipeline --hash-length 2` | 生成 `assets/generated/`、`counts.json`、`worker/targets.js`、`worker/slot_formats.js` |
| `npm run build` | `vite build` | 清空并重建 `dist/`（三个 HTML 入口 + 静态文件 + 图片池） |
| `npm run build:all` | `npm run gen && npm run build` | 完整构建（先生成，再打包） |
| `npm run dev` | `vite` | 本地开发服务，直接从 `assets/generated/` 提供图片与 `counts.json` |
| `npm run preview` | `vite preview` | 静态预览 `dist/`（**不执行 Worker**） |
| `npm test` | 两套 Python 测试 + 两套 Node 测试 | 只读测试，不修改仓库图片池 |
| `npm run lint` | `eslint .` | ESLint 检查（flat config） |
| `npm run typecheck` | `tsc --noEmit` | 类型门禁（`vite build` 只转译不做类型检查） |
| `npm run deploy` | `wrangler deploy` | 部署 `worker/index.js` 与 `./dist` 到 Cloudflare Workers |

验证 Worker 运行时与访问策略需先 `npm run build`，再运行 `npx wrangler dev --local`（本地环境变量可从 `.dev.vars.example` 复制为 `.dev.vars`）。

### `vite.config.ts` 的两个自定义插件

生成池体积约 1 GB 且被 git 忽略，因此不放进 `publicDir`（`assets/static`），而由两个插件接入根路径：

- **`srp:generated-assets-dev`（serve）**：挂载在 Vite 自有中间件之前，将 `/counts.json` 与 `/<cat>/<hex>.<ext>` 直接映射到 `assets/generated/`（含路径穿越校验与 `HEAD` 处理）。
- **`srp:generated-assets-build`（build）**：在 `closeBundle` 阶段将 `assets/generated/` 的分类目录与 `counts.json` 串行拷入 `dist/`；若 `assets/generated/` 缺失则直接抛错提示先跑 `npm run gen`。

### 注意事项与危险操作

- **不要在仓库根直接跑 `python -m pipeline --no-copy`**：会把 `assets/generated/` 里的真实图片覆写为 1×1 占位字节；误操作后重新执行 `npm run gen` 即可恢复。
- **不要手改生成物**：`assets/generated/counts.json`、`worker/targets.js`、`worker/slot_formats.js` 由管线重写，CI 会用 `git diff --exit-code` 校验同步。
- **不要把图片池放进 `assets/static/`**：`assets/static/` 是手写静态目录，会直接入库。
- **Windows 下重建 `dist/`**：先停掉占着 `dist/` 句柄的 `wrangler dev` 进程，避免 `EPERM`。

## 2. 代码规范

### 通用约定

- 行尾统一 LF（`.gitattributes`），文件末尾保留换行，非 Markdown 去除尾随空格（`.editorconfig`）。
- 缩进：默认 2 空格；`*.py` 与 `worker/*.js` 为 4 空格。
- 注释解释“为什么”（被否决的方案、顺序约束、平台坑），不复述代码字面意思。
- 生成的数据模块首行固定为 `// Generated by \`python -m pipeline\`. Do not edit.`。

### 各语言边界

| 模块 | 规范要点 |
| :--- | :--- |
| **TypeScript / React (`src/`)** | 函数组件：`src/components/*` 具名导出、`src/pages/*` 默认导出；统一 `@/` 别名；`strict: true`，无 `"use client"`；双语文案全部进 `src/lib/*-translations.ts`；交互控件补齐 `aria-*` 与可见焦点。 |
| **Python (`pipeline/`, `tests/*.py`)** | 仅用标准库，不引入第三方依赖；路径统一用 `pathlib.Path`；写文件固定 `newline='\n'`；CLI 参数集中在 `Config.from_args()`；公开函数带类型标注。 |
| **Worker JS (`worker/`)** | 纯 ESM、无框架、单引号 + 分号；修改响应头前先 `new Headers(response.headers)` 克隆；策略逻辑集中在 `worker/policy.js`，源码绝不硬编码域名或白名单。 |

### ESLint（`eslint.config.mjs`）

- 忽略 `dist/**`、`build/**`、`.wrangler/**`、`node_modules/**`、`assets/**`、`worker/targets.js`、`worker/slot_formats.js`。
- JS 启用 `recommended` + Node 全局；TS/TSX 启用 `typescript-eslint` recommended + `react-hooks`（`rules-of-hooks` error、`exhaustive-deps` warn）；未使用变量默认 warn，`_` 前缀豁免。

## 3. 测试套件

`npm test` 依次运行四套测试，任一失败即中断：

| 套件 | 单独运行 | 覆盖范围 |
| :--- | :--- | :--- |
| `tests/pipeline/test_pipeline.py` | `python tests/pipeline/test_pipeline.py` | 图片头尺寸/格式嗅探、后缀漂移报告与 `--strict-formats` 零写入、`slot_formats.js` 循环映射、Schema 契约校验、时间戳复用、空扫描零写入、真实树漂移不增长门禁 |
| `tests/test_access_policy.py` | `python tests/test_access_policy.py` | 静态源码断言：7 个策略环境变量均被读取、运行时不含 `ACCESS_POLICY`/`srprolin` 等部署值、`targets.js` 与清单一致、`slot_ratios` 长度匹配槽位数 |
| `tests/backend-contract.test.mjs` | `node --test tests/backend-contract.test.mjs` | 真实 `node:http` 驱动 `worker/index.js`：状态码、CORS 预检、拒绝与 404 同形、非法 env fail closed（500）、`Vary`/`Cache-Control`、真实 MIME 纠正、`wrangler.jsonc` 不含 `vars` 且开启 `run_worker_first` |
| `tests/worker/source-equivalence.test.mjs` | `node --test tests/worker/source-equivalence.test.mjs` | 与历史单文件生成入口 `git show HEAD:index.js` 的 1640 组差分矩阵；旧入口已移除，`HEAD` 不存在该文件时自动 `skip` |

### 漂移基线守卫

`GeneratedArtifactGateTests` 对真实素材树设定只降不增基线：

- 源文件：`a: 56`、`gif: 0`、`h: 43`、`v: 7`
- 槽位：`a: 125`、`gif: 0`、`h: 81`、`v: 28`

修正历史素材后可调低常量；未列入的新增分类允许值为 `0`，确保同构新分类无需改测试即可通过。

## 4. 协作与工作流

### 提交约定

遵循 Conventional Commits（`feat:`、`fix:`、`docs:`、`refactor:`、`chore:`）。如果修改了 `pipeline/`、`worker/` 或 `assets/original/`，须同时提交重新生成的 `assets/generated/counts.json`、`worker/targets.js`、`worker/slot_formats.js`。

### 测试工作流（`.github/workflows/test.yml`）

触发条件：`pull_request` 与手动 `workflow_dispatch`（推 `main` 由部署工作流接管，避免重复构建），按 ref 分组 `cancel-in-progress: true`。

步骤顺序：Node 22 + Python 3.12 → `npm ci --ignore-scripts` → `npm run lint` → `python -m pipeline --no-copy --hash-length 2` → `git diff --exit-code -- worker/targets.js worker/slot_formats.js assets/generated/counts.json` → `npm run build` → `npm test` → `npm run typecheck`。

CI 使用 `--no-copy` 可跳过复制 1 GB 真实图片，但 `counts.json`、`targets.js`、`slot_formats.js`（只读源文件头）与全量生成逐字节一致，因此既快又能准确拦截过期生成物。

### 部署工作流（`.github/workflows/deploy.yml`）

触发条件：推送到 `main`（`paths-ignore` 跳过纯 `**.md` 与 `LICENSE` 改动）或手动 `workflow_dispatch`；`cancel-in-progress: false` 防止并发竞态部署。

步骤：安装依赖 → `python -m pipeline --hash-length 2`（**真拷贝**）→ `npm run build` → `npx wrangler deploy`（使用仓库 Secrets 中的 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`）。

### 提交前本地自检

```bash
npm run lint
npm run build
npm test
npm run typecheck
git status --short
```
